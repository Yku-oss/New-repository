## 1. JWT 认证（JD 要求，简历也写了"了解"）

**一句话**：登录后服务端签发一个带签名的令牌，客户端带着它访问，验签通过就放行——**全程无状态**。

**结构（三段，点分隔）**：`header.payload.signature`
- header：算法（HS256）、类型
- payload：用户信息 + 过期时间
- signature：签名（防篡改）

**认证流程（背）**：
> 登录 → 服务端验证账号密码 → **签发 JWT** → 客户端存 token，每次请求放 **Authorization 头**（`Bearer xxx`）→ 服务端**验签** → 信任 token 里的 userId → 放行

**和 Session 对比**：Session 服务端存状态要查；JWT 客户端带 token 验签即可，天然适合多台服务器。缺点是签发后难主动失效。

**记忆锚**：**登录签发 → 请求带 token → 验签放行，全程无状态。**

## 2. 短链接 5 问（标准答法）

### Q1 短码为什么用"自增ID + Base62"？不用 UUID / 分布式锁？
> "短码要又短又唯一。UUID 唯一但 32 位太长，直接排除；分布式锁能保证唯一，但每次生成都要锁协调，高并发下是瓶颈。我用数据库自增 ID——唯一性交给 MySQL 自增保证，应用层零协调，吞吐高。代价：先插后更（多一次 UPDATE 回写）、依赖单库自增（分库分表要演进成雪花算法）、短码可被枚举（要加随机化）。"

### Q2 缓存命中率怎么来的？穿透/击穿/雪崩？
> "造了 300 万条测试数据压测对比：走 Redis 缓存接口 vs 直接查 MySQL 接口，DB QPS 下降约 60%；命中率 70% 看日志——70% 请求命中缓存，30% 回源。"
- **穿透**（数据不存在）：缓存空值 / 布隆过滤器
- **击穿**（单个热点 key 过期）：互斥锁（只让一个请求重建）/ 逻辑过期
- **雪崩**（大批 key 同时过期）：过期时间加随机值 / 多级缓存（本地+Redis）
- 收尾加分："我的项目主要防穿透——查不存在的短码，把空值也缓存。"

### Q3 异步日志为什么 AOP + 线程池？
> "同步写 = 请求线程自己写库，每次跳转多一次 DB 写，高并发下接口被拖垮。AOP 是横切关注点，日志采集不污染业务代码。改成异步：主线程把任务丢给线程池立即返回，后台线程写库。日志是非核心数据，队列有界，满了优先 CallerRunsPolicy，极端允许丢弃，绝不让日志拖垮主业务。"

### Q4 TopN 为什么用 ZSet？
> "TopN 是排行榜场景，ZSet 量身定做。每次访问 ZINCRBY 原子加一，查询 ZREVRANGE 倒序取前 N。不用 MySQL 是因为实时排序对 DB 压力大（适合定时任务离线算）。底层 = 哈希表（O(1) 找成员）+ 跳表（O(logN) 排序）。"

### Q5 全局异常处理器？
> "用 @RestControllerAdvice 定义全局异常处理器（= @ControllerAdvice + @ResponseBody），@ExceptionHandler 分别处理业务异常和兜底异常，统一返回 {code, message, data}。业务异常给明确提示，系统异常兜底返回'系统繁忙'，不泄露堆栈。格式统一，所以联调时间降了 30%。"

## 3. 网络基础（JD 要求）

### TCP 三次握手（方向别反）
> **客户端**发 SYN → **服务端**回 SYN+ACK → **客户端**回 ACK。确保双方收发都通，避免历史失效请求误建连接。

### HTTP vs HTTPS
> HTTPS = HTTP + TLS 加密层。三个区别：**加密（防窃听）/ 证书认证身份（防伪造）/ 完整性（防篡改）**。端口 80 vs 443。

### 状态码（背 8 个）
- 200 成功 ｜ 301 永久重定向 / 302 临时重定向
- **401 没登录 / 403 没权限**（绑一起记！）
- 404 不存在 ｜ 500 服务器错误 / 502 网关错误

## 4. 高频八股一句话（扫一眼，能接上就行）

- **B+树**：矮胖 + 叶子有序链表 → 范围查询；红黑树太高、哈希不支持范围
- **聚簇/非聚簇**：聚簇叶子存整行（主键）；二级索引叶子存主键 → 回表；覆盖索引免回表
- **事务隔离**：脏读/不可重复读/幻读；RR 是 MySQL 默认
- **MVCC**：隐藏字段（DB_TRX_ID 谁改的 + DB_ROLL_PTR 上一版）+ undo 版本链 + ReadView（没提交的看不到）；快照读不加锁；RR 复用 ReadView
- **间隙锁**：当前读防幻读；快照读靠 MVCC
- **Redis 三兄弟**：穿透=数据不存在（空值/布隆）；击穿=单热点过期（互斥锁/逻辑过期）；雪崩=大批过期（随机时间/多级缓存）
- **线程池**：core → 队列 → max → 拒绝策略（Abort/CallerRuns/Discard）；7 参数
- **volatile**：可见性 + 有序性，不保证原子性
- **Spring**：IOC 控制反转（对象交给容器）、AOP 横切（日志/事务）；SpringMVC 流程 = 请求 → DispatcherServlet → HandlerMapping → Controller → 返回
