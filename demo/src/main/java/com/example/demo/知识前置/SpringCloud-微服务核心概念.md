# Spring Cloud / 微服务核心概念（JD 常写"了解 Spring Cloud"）

> 用途：JD 上常见这项，不用精通整套，**懂这 5 个核心概念 = 面试能接话**（2026-09-17 建）。
> 定位：初级/实习岗一般不硬卡微服务实战；但 JD 写了，能讲概念就不吃亏。

---

## 一、为什么要微服务（单体 → 微服务）

- **单体架构问题**：所有功能在一个项目里，改一处要整个重新部署；某个模块崩了可能全挂；扩容只能整体扩。
- **微服务**：把系统拆成**多个独立的小服务**（用户服务、订单服务、商品服务…），各自**独立开发、部署、扩容**。
- **代价**：服务变多 → 带来**服务发现、调用、治理**等新问题 → 这些就是 Spring Cloud 要解决的。

## 二、五大核心组件/概念

### 1. 服务注册与发现（注册中心）
- **问题**：服务 A 要调服务 B，但 B 的实例地址会变（扩容/重启），A 怎么知道 B 在哪？
- **做法**：所有服务启动时**到注册中心"报到"**（注册自己的地址）；要调别的服务时**去注册中心查**。
- **常见**：Nacos、Eureka

### 2. 远程调用（服务间怎么调）
- **做法**：像调本地方法一样调远程服务，底层是 **HTTP 请求**（封装好）。
- **常见**：OpenFeign（声明式调用）、RestTemplate

### 3. 网关（统一入口）
- **做法**：所有外部请求**先过网关**，由网关**路由**到对应服务，并统一做 **鉴权 / 限流 / 日志**。
- **常见**：Spring Cloud Gateway、Zuul
- **面试点**：网关 = 系统的唯一入口，对外屏蔽内部服务结构

### 4. 熔断与降级（故障隔离）
- **问题**：服务 C 挂了，调用它的服务全被拖死（雪崩）→ 整条链路崩
- **做法**：调用失败到一定比例就**快速失败（熔断）**，返回**兜底数据（降级）**，不让故障扩散
- **常见**：Sentinel、Hystrix

### 5. 配置中心（统一配置）
- **做法**：配置集中管理，支持**动态刷新**（改配置不用重启服务）
- **常见**：Nacos、Spring Cloud Config

## 三、一句话串联（面试可以这么说）

> "微服务是把单体按业务拆成多个独立部署的小服务。拆开后需要 Spring Cloud 这层治理：**注册中心**让服务互相发现、**Feign** 做远程调用、**网关**作为统一入口做路由和鉴权、**Sentinel** 熔断降级防止故障扩散、**配置中心**统一管理配置。"

## 五、要不要深学？
- **初级/实习岗**：懂上面概念即可，**不用搭整套 Cloud 项目**
- **想升级/大厂**：再挑 1-2 个组件（如 Nacos + Feign）做个小 demo
- **优先级**：基础八股（IoC/AOP/MySQL/Redis/并发）+ 项目 > Spring Cloud
