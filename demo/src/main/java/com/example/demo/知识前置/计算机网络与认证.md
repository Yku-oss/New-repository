## 1. TCP 三次握手

**一句话结论**：客户端发 SYN → 服务端回 SYN+ACK → 客户端回 ACK；目的是双方互相确认"收发都通"，并避免历史失效请求误建连接。

SYN = 同步请求，ACK = 确认应答。三次握手的核心是**互相确认"你发我收"都通**。

追问链：
- 为什么是三次不是两次？→ 第三次 ACK 是客户端确认"我收到了服务端的应答"；两次无法确认客户端接收能力，且无法避免旧连接请求误建
- 挥手是几次？→ 四次（FIN/ACK），因为 TCP 全双工，两边各自关闭

**记忆锚**：谁发起连接谁先发 SYN；三次 = 互相确认"你发我收"都通。

## 2. HTTP 与 HTTPS

**一句话结论**：HTTPS = HTTP + TLS 加密层，在明文 HTTP 上加了加密、身份认证、完整性三层保护。

追问链：
- 三个区别？→ ① 数据加密（防窃听）② 证书认证服务器身份（防伪造）③ 完整性校验（防篡改）
- 端口？→ HTTP 80 / HTTPS 443
- 为什么必须用 HTTPS？→ 明文传输敏感数据会被中间人窃听/篡改

**记忆锚**：加密 + 认证 + 完整性。

## 3. 常见状态码

- 2xx：**200** 成功
- 3xx：**301** 永久重定向 / **302** 临时重定向 / 304 未修改（缓存）
- 4xx：400 请求错误 / **401 未认证（没登录）** / **403 没权限（登录了但不够格）** / 404 不存在
- 5xx：**500** 服务器内部错误 / **502** 网关错误 / 503 服务不可用

**记忆锚**：401 没登录，403 没权限——绑一起记，最容易混。

## 4. JWT 认证

**一句话结论**：登录后服务端签发一个带签名的令牌，客户端带着它访问，验签通过就放行——**全程无状态**。

**结构（三段，点分隔）**：`header.payload.signature`
- header：算法（如 HS256）、类型
- payload：用户信息（userId）+ 过期时间（exp）
- signature：签名（header + payload 用密钥哈希），防篡改的关键

**认证流程**：
登录 → 服务端验证账号密码 → 签发 JWT 返回 → 客户端存 token，请求放 **Authorization 头**（`Bearer xxx`）→ 服务端**验签** → 信任 payload 里的 userId → 放行

追问链：
- 和 Session 区别？→ Session 服务端存状态要查（有状态）；JWT 客户端带 token 验签即可（无状态），天然适合多台服务器/微服务
- JWT 缺点？→ 签发后难主动失效（要等过期）、不能踢人；payload 别放敏感信息（base64 可解码）
- **OAuth2 和 JWT 关系？**→ OAuth2 是**授权框架**（流程），JWT 常作为 OAuth2 里 access token 的**载体**（格式）——两个概念，别混

**记忆锚**：登录签发 → 请求带 token → 验签放行，全程无状态。
