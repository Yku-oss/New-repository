## 一、集群 vs 分布式

| | 是什么 |
|---|---|
| **集群** | 多台机器组队，目的：**① 扛更大负载**（性能/容量）**② 高可用**（一台挂了有备份）|
| **分布式** | 任务/数据**分散到多台**处理（工作方式）|

- **主节点指挥、从节点干活**（如 Hadoop：NameNode 管元数据、DataNode 存数据）
- **集群是分布式系统的硬件基础**（Redis 集群、MySQL 主从集群同理）

## 二、CAP 定理（分布式第一原理）⭐

**C / A / P 三选二**：
| 字母 | 全称 | 意思 |
|---|---|---|
| **C** | Consistency 一致性 | 所有节点**同一时刻看到的数据一样** |
| **A** | Availability 可用性 | 每个请求**都能得到响应**（可以不最新，但不能不响应）|
| **P** | Partition tolerance 分区容错 | 网络分区（节点通信断了）时系统**还能工作** |

### 核心：P 必须选 → 实际是「CP 还是 AP」
- **为什么**：分布式里**网络分区必然发生**，你不能选"网络不出问题" → **P 必须有**
- 于是变成：**分区发生时，你保 C 还是保 A？**

| 类型 | 分区时保什么 | 例子 |
|---|---|---|
| **CP** | **宁可拒绝服务，也保证数据一致** | **ZooKeeper、Redis 集群、HBase** |
| **AP** | **宁可返回可能过期的数据，也保证可用** | **Eureka（注册中心）、Cassandra** |

⚠️ 易混：CP/AP 的**例子别记反**（曾把 ZK/Redis 说成 AP）。争的不是"新旧数据"，是"**分区时要不要拒绝服务**"。

### 为什么三者不能同时满足（理解本质）
分区发生时，节点 A、B 联系不上、数据可能不一致。此时来请求只能二选一：
- **保 C** → 节点**拒绝服务**（怕给不一致数据）→ 丢 A
- **保 A** → 节点**继续响应但可能返回旧数据** → 丢 C

> 一句话：**"P 发生时，C 和 A 必然冲突，只能保一个。"**

## 三、BASE 理论（选 AP 后的那套）【待学】
- **BA**（Basically Available）基本可用
- **S**（Soft state）软状态
- **E**（Eventually consistent）最终一致性
> 与 CAP 的 C 相对：**牺牲强一致，换取可用性，追求"最终一致"**。
